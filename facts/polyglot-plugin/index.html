Polyglot Plugin

Polyglot Plugin is a universal plugin package layout that makes a single skill or tool discoverable and usable by multiple AI agent harnesses simultaneously.

Polyglot Plugin operates in the AI agent extensibility segment. It targets coding agents, CLI agents, and IDE-based agents that each define their own plugin, skill, rule, or extension discovery paths.

Polyglot Plugin is distinct from a single-harness plugin (which targets one agent only) and from a marketplace (which is a registry of many independent plugins). A Polyglot Plugin is one package that contains the correct discovery artifact for each supported agent, all pointing at one canonical source of truth.

Polyglot Plugin: Package structure

A Polyglot Plugin is a root directory that contains a canonical Open Skills skill under .agents/skills/<name>/SKILL.md plus per-harness bridge artifacts. The SKILL.md file is the single source of truth. Every other artifact either imports, mirrors, or points to it.

The canonical layout: 

{{skill-name}}/
├── .agents/
│   └── skills/
│       └── {{skill-name}}/
│           ├── SKILL.md          # Canonical source of truth
│           ├── scripts/          # Executable tools (Python/Bash)
│           ├── references/       # Static knowledge docs
│           └── assets/           # Templates, raw data
├── .cursor/
│   └── rules/
│       └── {{skill-name}}.mdc   # Cursor discovery
├── .github/
│   └── copilot-instructions.md  # VS Code Copilot discovery
├── .grok/
│   └── config.toml              # Grok Build discovery
├── AGENTS.md                    # Codex / OpenAI / Kilo / Roo / Zed / Junie
├── ai-plugin.json               # Legacy OpenAI plugin manifest
├── mcp.json                     # MCP server definition
└── README.md                    # Human documentation

The folder name under .agents/skills/ must equal the name: field in SKILL.md frontmatter. Several harnesses fail silently when these mismatch.

Polyglot Plugin: Bridge artifacts

Bridge artifacts are per-harness files that map the canonical SKILL.md to each agent's discovery logic. They do not contain independent content; they import, mirror, or point to the canonical skill.

.agents/skills/<name>/SKILL.md
Canonical source of truth. Satisfies all Open Skills-compatible harnesses.
.cursor/rules/<name>.mdc
Cursor rule file that imports or inlines the skill body.
.github/copilot-instructions.md
VS Code Copilot workspace-level instructions, condensed from the skill.
AGENTS.md
Always-on instructions for Codex, Kilo, Roo, Zed, Junie, and other AGENTS.md readers.
.grok/config.toml
Grok Build skill path pointer.
mcp.json
MCP server definition for all MCP-capable harnesses (Claude Code, Cursor, Kiro, Cline, etc.).
ai-plugin.json
Legacy OpenAI plugin manifest for generic plugin harnesses and backward compatibility.

Polyglot Plugin: Critical invariants

The following invariants are enforced by the polyglot-plugin generator and must hold for every generated package:

  1. The folder name under the skills root equals the name: frontmatter field (kebab-case). Harnesses such as Kiro fail silently when these mismatch.
  2. The description field is a trigger for embedding-based matchers, not marketing copy. It must state what the skill does and when to use it.
  3. Prefer stdio MCP for live tools. Never embed secrets in manifests; use environment references.
  4. Keep SKILL.md lean. Move bulk reference material to references/.
  5. Never install an entire marketplace as one plugin unit. A marketplace is a registry of many independent plugins.

Distinguishing Polyglot Plugin

Polyglot Plugin is not the same as any of the following related concepts:

Not a single-harness plugin
A single-harness plugin targets one agent (e.g., a Claude Code plugin or a Cursor plugin). A Polyglot Plugin targets many agents from one package.
Not a marketplace
A marketplace is a registry of many independent plugins. A Polyglot Plugin is one package that works across harnesses. Users install one unit at a time.
Not the Open Skills standard itself
Open Skills (agentskills.io) defines the SKILL.md folder format. Polyglot Plugin uses Open Skills as its canonical source of truth and adds per-harness bridge artifacts around it.
Not MCP
MCP (Model Context Protocol) is a protocol for live tools, resources, and prompts. Polyglot Plugin packages may include an MCP server via mcp.json, but MCP is one transport layer, not the package format.
Not AGENTS.md
AGENTS.md is an always-on instruction file convention. A Polyglot Plugin may include an AGENTS.md bridge, but the canonical source is the SKILL.md, not the instructions file.
Not a tool or script collection
Scripts in scripts/ are optional executable helpers. The package format is defined by the discovery artifacts and the canonical SKILL.md, not by the scripts.

Polyglot Plugin: Related entities

The following related entities are part of the polyglot-plugin project domain. Each is a separate entity with its own facts:

  • Open Skills / Agent Skills — the SKILL.md folder standard maintained at agentskills.io. The canonical source format used by Polyglot Plugin.
  • Model Context Protocol (MCP) — the open protocol for exposing live tools, resources, and prompts to AI agents. Used as the transport layer for executable tools in a Polyglot Plugin.
  • AGENTS.md — the always-on instruction file convention used by Codex, Kilo, Roo, Zed, Junie, and others. One of the bridge artifacts in a Polyglot Plugin.
  • OKF plugin-type knowledgebase — the dated, living knowledgebase of what each AI agent harness calls plugins, skills, rules, and extensions. Maintained at references/okf-plugin-type-things-2026-07.md and expanded in the okf-plugin-type-things-knowledge-package-2026-07/ directory.
  • polyglot-plugin skill — the generator skill that produces Polyglot Plugin packages from a purpose description. See the repository.
  • convert-to-polyglot skill — the migration skill that converts an existing single-harness plugin into the polyglot layout.
  • plug-me-in skill — the consumer skill that detects the current harness and installs a skill, plugin, MCP server, or marketplace unit into it.

FAQ about Polyglot Plugin

What is a Polyglot Plugin?

A Polyglot Plugin is a universal plugin package layout that makes one skill or tool discoverable by multiple AI agent harnesses from a single directory. It uses a canonical SKILL.md as the source of truth and emits per-harness bridge artifacts.

Why is a Polyglot Plugin needed?

No single file format satisfies every AI agent. Each harness defines its own discovery paths, manifest schemas, and terminology. A Polyglot Plugin provides the correct artifact for each harness while maintaining one canonical source of truth.

How does a Polyglot Plugin differ from an Open Skills skill?

An Open Skills skill is a single SKILL.md folder. A Polyglot Plugin wraps an Open Skills skill as its canonical core and adds bridge artifacts (Cursor rules, AGENTS.md, MCP config, Grok config, Copilot instructions, legacy manifest) so the same skill is discovered by harnesses that do not natively scan .agents/skills.

Which agents support Polyglot Plugin packages?

Claude Code, Cursor, OpenAI Codex CLI, GitHub Copilot, VS Code, Devin, Windsurf, Gemini CLI, OpenCode, Kiro, Warp, Grok Build, Cline, Kilo Code, and Qwen Code. Additional harnesses are covered in the OKF knowledgebase.
